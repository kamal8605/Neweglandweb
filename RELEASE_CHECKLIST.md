# Production Release Checklist

Storefront: `fastweb-master-main` (Next.js 16, Vercel) · API + admin: `gateway-main` (Laravel 13, Hostinger).

## 1. Before deploying

### Backend (`gateway-main`, Hostinger)
- [ ] **Back up the production database** (Hostinger panel → Databases → Backups, or `mysqldump`) and `storage/app/public` (uploaded logos, banners, catalog PDFs).
- [ ] `.env` on the server:
  - `APP_ENV=production`, `APP_DEBUG=false` (verified off on 5 Oct 2026: errors return only `"Server Error"`).
  - `CORS_ALLOWED_ORIGINS=https://neweglandweb.vercel.app` (plus the custom domain once it exists). Unset = `*`.
  - `JWT_SECRET` set; `MAIL_*` set to a real mailbox (password-reset e-mails).
  - `QUEUE_CONNECTION=database` **and a running queue worker** (cron: `* * * * * php artisan schedule:run` plus `php artisan queue:work --stop-when-empty` every minute, or a supervisor). Without a worker, orders are saved but never sent to the ERP.
- [ ] Deploy code, then run `php artisan migrate --force` (adds `cart_items`; additive only, no existing data touched).
- [ ] `php artisan config:cache && php artisan route:cache`.

### Frontend (`fastweb-master-main`, Vercel)
- [ ] Environment variables (Production):
  - `NEXT_PUBLIC_API_URL=https://hotpink-parrot-228156.hostingersite.com`
  - `NEXT_PUBLIC_SITE_URL=https://neweglandweb.vercel.app` (or the custom domain): used for canonical URLs, `sitemap.xml`, `robots.txt`.
  - `NEXT_PUBLIC_HOMEPAGE_CLIENT=new-england`
- [ ] Commit `public/pdfjs/pdf.worker.<version>.legacy.min.mjs` (generated by `npm run build`; the catalog viewer needs it on older iPads).
- [ ] **Deploy the backend first**, then the frontend (the frontend calls `/api/cart`).

## 2. Smoke test right after deploying (5 minutes)
- [ ] Home page loads with banners, categories, products; no errors in the browser console.
- [ ] `/shop` lists products; search, a filter and sorting work; open a product.
- [ ] Open a catalog (desktop and phone/iPad).
- [ ] Log in → cart badge loads → add a product → open the site in a second browser with the same account → same cart.
- [ ] Wishlist: add on one browser, see it on the other.
- [ ] Checkout with a test account → order page opens → order appears in the admin panel and (after the worker runs) in the ERP.
- [ ] Log out → cart badge disappears; log in as another account → empty cart.
- [ ] `https://<site>/robots.txt` and `https://<site>/sitemap.xml` open.
- [ ] Admin panel login works; non-admin user gets 403 on `/admin`.

## 4. Known limitations (by design or out of scope)
- **No online payment**: orders are created with `payment_status = due` (invoice/wholesale terms). There is no payment gateway to test.
- **Shipping, tax and discounts are not calculated online**: the cart shows "Shipping: TBD" and prices are net of tax; the order total is the sum of catalog prices. Client-sent totals are ignored.
- **Password reset** from the storefront is a `mailto:` link to sales; the API endpoint exists and sends Laravel's reset e-mail, which opens the Laravel reset page.
- **Very old iPads** (iPadOS below 14) are not supported by the framework.
- `web-auth/webauthn-lib` (low-severity advisory) is pinned by `laravel/fortify` → `laravel/passkeys`; it clears when Fortify is upgraded.

## 5. Rollback
- Frontend: Vercel → Deployments → previous deployment → "Promote to Production" (instant).
- Backend: redeploy the previous release. The `cart_items` migration can stay (nothing else depends on it); if needed, `php artisan migrate:rollback --step=1` drops only that table.
- Database: restore the backup from step 1 only if data was damaged.

## 6. Monitoring after launch
- Laravel: `storage/logs/laravel.log` (failed orders are logged at `emergency`, ERP queue failures at `error`; failed ERP jobs set the order's `sync_status` to `failed`).
- Vercel: Project → Logs / Observability for server-side errors.
- Check the admin orders list daily for `sync_status = failed` during the first week.
